# План публикации сайта FutureKinetix на GitHub Pages

Итог: постоянная бесплатная ссылка вида `https://ВАШ_ЛОГИН.github.io/имя-репозитория/`
(или `https://futurekinetix.github.io/`, если завести орг-аккаунт) + возможность подключить свой домен.
Ориентировочное время: **~40 минут без своего домена**, ~1–2 часа с доменом (ожидание DNS).

Что публикуем: папка **`site/publish/`** — 6 HTML-страниц + служебный файл `.nojekyll`:
`index.html`, `products.html`, `yarbo.html`, `automation.html`, `company.html`, `contacts.html`, `.nojekyll`.
Все ссылки между страницами относительные, стили и фото встроены — сайт работает и в корне домена, и в подпапке `/имя-репозитория/` без правок.
`.nojekyll` отключает сборку Jekyll на GitHub Pages, чтобы файлы отдавались как есть (точки-файлы вроде `.nojekyll` тоже сохраняются).

---

## Этап 0. Подготовка (5 мин)

1. Убедитесь, что в `site/publish/` лежат 7 файлов (6 страниц + `.nojekyll`).
2. Проверьте актуальность: если правили `build.py`, сначала `python3 build.py`, затем скопируйте 6 html в `publish/`.
3. Приготовьте e-mail для регистрации GitHub и браузер (для способа без git) или установленный git (для CLI-способа).

## Этап 1. Аккаунт GitHub (5–10 мин)

1. <https://github.com> → **Sign up**: e-mail, пароль, логин. Рекомендую логин-бренд: `futurekinetix`.
2. Подтвердите e-mail по письму.
3. (Рекомендуется) Settings → Password and authentication → включите 2FA.
4. Важно: на бесплатном тарифе GitHub Pages работает **только для публичных репозиториев** — создаём Public.

## Этап 2. Репозиторий (5 мин) — два варианта на выбор

**Вариант A — «красивый» корневой адрес (рекомендую для компании):**
1. Создайте **организацию**: Settings → Organizations → New organization (Free): имя `futurekinetix`.
2. Внутри организации создайте репозиторий с именем **`futurekinetix.github.io`** (Public).
3. Итоговый адрес сайта: `https://futurekinetix.github.io/` (без подпапки).

**Вариант B — быстрый, от личного аккаунта:**
1. Кнопка «+» → **New repository**, имя `futurekinetix-site`, видимость **Public**, галочку README можно не ставить.
2. Итоговый адрес: `https://ВАШ_ЛОГИН.github.io/futurekinetix-site/`.

## Этап 3. Загрузка файлов (10 мин) — три способа, выберите один

### Способ 1. Через браузер (без git) — проще всего
1. Откройте страницу репозитория → **Add file → Upload files**.
2. Перетащите все 7 файлов из `site/publish/` (включая `.nojekyll`; если точка-файл не подхватился драг-н-дропом — создайте его отдельно: **Add file → Create new file**, имя `.nojekyll`, содержимое пустое, Commit).
3. Нажмите **Commit changes**.

### Способ 2. Через git в терминале
```bash
cd site/publish
git init -b main
git add .
git commit -m "FutureKinetix site v1"
git remote add origin https://github.com/ЛОГИН/ИМЯ_РЕПО.git
git push -u origin main
```
При первом push браузер попросит войти в аккаунт (Credential Manager / Personal Access Token).

### Способ 3. GitHub Desktop
File → Add Local Repository → выбрать папку `site/publish` → Publish repository → имя и Public → Publish. Далее — Commit и Push из интерфейса.

## Этап 4. Включить GitHub Pages (5 мин)

1. В репозитории: **Settings → Pages**.
2. Build and deployment: **Source = Deploy from a branch**; **Branch = main**, папка **/ (root)** → **Save**.
3. Откройте вкладку **Actions**: появится workflow «pages build and deployment», дождитесь зелёной галочки (1–3 минуты).
4. Ссылка на сайт: баннер на Settings → Pages или сразу `https://ЛОГИН.github.io/ИМЯ_РЕПО/` (вариант A: `https://futurekinetix.github.io/`).

## Этап 5. Проверка после деплоя (10 мин) — чек-лист

- [ ] Открывается главная, все фото и стили на месте.
- [ ] Работают все 6 пунктов меню и логотип (переходы между страницами).
- [ ] Якоря каталога: `products.html#clean`, `#warehouse`, `#arm`, `#delivery`, `#drone`, `#dog`.
- [ ] Кнопки «Запросить подробности» открывают `contacts.html` с предвыбранной темой в форме.
- [ ] На `yarbo.html`: галерея (4 миниатюры), переключатель комплектаций меняет цену, вкладки характеристик, 3 видео-карточки проигрываются (нужен интернет у зрителя).
- [ ] Форма заявки показывает подтверждение после отправки.
- [ ] Сайт открывается со смартфона (меню-бургер).
- [ ] Адрес начинается с `https://` (сертификат выпускается автоматически).

## Этап 6. Свой домен (опционально, 30–60 мин + DNS до 24 ч)

1. Купите домен, напр. `futurekinetix.ru` (reg.ru / nic.ru, ~500–900 ₽/год).
2. В репозитории: **Settings → Pages → Custom domain** → впишите домен → Save (в корне репозитория сам появится файл `CNAME`).
3. У регистратора домена пропишите DNS-записи:
   - `A  @  185.199.108.153`
   - `A  @  185.199.109.153`
   - `A  @  185.199.110.153`
   - `A  @  185.199.111.153`
   - `CNAME  www  ЛОГИН.github.io`
4. Дождитесь применения DNS (от минут до суток), затем на Settings → Pages включите **Enforce HTTPS** (сертификат Let's Encrypt появится за минуты–час).
5. Готово: сайт живёт на `https://futurekinetix.ru`, а старый адрес github.io продолжает работать как редирект.

## Этап 7. Обновление сайта в будущем

После любых правок (`build.py` → `python3 build.py` → копия 6 html в `publish/`):
```bash
cd site/publish
git add -A
git commit -m "обновление сайта"
git push
```
Через 1–2 минуты новая версия сама опубликуется. Без git: просто повторно загрузите изменённые файлы через Add file → Upload files.

## Troubleshooting

| Симптом | Причина и решение |
|---|---|
| 404 при открытии | Settings → Pages: ветка `main`, папка `/ (root)`; имена файлов строчные; подождите завершения Actions |
| Страница без картинок | Файл не догрузился: проверьте в репозитории размер html (1–2,5 МБ) и дозалейте |
| Показывается старая версия | Кэш браузера: Ctrl+F5; либо деплой ещё идёт: вкладка Actions |
| Сайт в подпапке «ломается» | Не ломается: все ссылки относительные. Но для красоты используйте вариант A или свой домен |
| Видео не играет | YouTube недоступен в сети зрителя — это не ошибка сайта |
| Ошибка «push rejected» | Первый push в непустой репозиторий: `git pull --rebase origin main` или создайте репозиторий без README |
| Нужно скрыть код сайта | На бесплатном тарифе репозиторий публичный; для приватного + Pages нужен платный план — тогда проще Netlify (см. HOSTING.md) |
